**Current setup:** See [SETUP-AND-FEATURES.md](../SETUP-AND-FEATURES.md). The management upgrade is already applied to the connected project. The instructions below describe the earlier additions; do not reapply them to the current database.

1. Apply the migration files in order in the Supabase SQL editor or through the Supabase CLI. The first adds alumni, notifications, and director operations; the second adds secure member profile editing; the third refreshes Supabase's API schema cache so the new publishing functions become available; the fourth creates the secure resource-upload bucket.
2. Add alumni in `alumni_profiles`; the member-facing directory reads the privacy-safe `alumni_directory` view.
3. Deploy `functions/send-notification-email --no-verify-jwt` and configure the secrets `RESEND_API_KEY`, `NOTIFICATION_FROM_EMAIL`, and a random `WEBHOOK_SECRET`. The function verifies the separate webhook secret itself.
4. Create a Supabase Database Webhook for inserts on `member_notifications`, pointing to the deployed Edge Function. Add an `x-webhook-secret` header whose value matches `WEBHOOK_SECRET`. This keeps the email provider key out of the browser.

The database change creates in-app notifications immediately. Email delivery begins once the function, sender domain, and webhook are configured.
